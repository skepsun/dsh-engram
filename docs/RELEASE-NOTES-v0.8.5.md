# dsh-engram v0.8.5

**一条实验驱动的改动：记忆指向的文件变了，行上会写出来。**

## 反向实验发现了什么

`docs/G6-quality-ab.zh.md` §9：同一个仓库，代码里有 bug、docstring 写着正确约定，
预置记忆换成 5 条**过时的错误约定**。6 个任务里 agent 有 1 个照抄了错记忆并挂掉——
不是随机失手，它在日志里先写下「audit log 通常是 UTC」，然后用仓库里那句
「按团队口径写」说服自己服从记忆。

另外 5 个任务里，agent 靠**记忆行上的日期**（`2026-09 记录`）判断出这条是旧的。
所以日期不是装饰，是可被用来降权的证据——索引行和召回行本来就带 `createdAt`。

## 这次补的口子：`filePath` 但没有 anchor 的记忆

已有的一半：带 anchor 哈希的记忆，文件变了会直接掉出索引（`memoryIsStale`）。
但还有一批记忆只是**提到**某个文件（本仓库 402 行里 62 行有 `filePath`），
它们没有任何信号告诉模型「这行写的文件后来被改过」。

现在索引行和 `[RECALL]` 行会带一个标记：

```
[D] 09-14 …… #9b585a1b ⚠file-changed
[D] 08-02 …… #61c0ffee ⚠file-missing
```

- `⚠file-changed`：锚定文件的 mtime 晚于记忆的 `createdAt`
- `⚠file-missing`：文件已不存在（比「什么都没说」诚实）
- 没有 `filePath`、没有时间戳、stat 失败 → 什么也不加，且**永不抛错**（注入路径不能因为一个坏路径炸掉）

一次 `stat` 换一个可核实的信号；20 行索引对它来说不算成本（G7 仍远低于 0.5%）。

## 证据

- `npm test` **481/481**（+4：changed / unchanged / missing / 无锚点不抛）
- G6 反向实验：`eval/g6/runs/stale-a/REPORT.md`（12 对，复制率 1/6）

## 附：G6 的 +30pp 已撤回（同日深夜）

第三轮用 macOS seatbelt 做了内核级读黑名单（`--sandbox`），同一语料重跑：
**Δ 从 +30.0pp 缩到 +8.3pp**（12 对，控制臂平均耗时 743s → 116.5s）。原因不是数字
挑拣，是第二轮的环境同时污染两臂、方向不明——控制臂把时间花在找泄漏上。
更关键的发现：这个语料的「规格」其实写在 `src/*.js` 的 docstring 里，
**不满足「不可推导」**，测不出记忆价值。

详见 `docs/G6-quality-ab.zh.md` §10。G6 门槛本身没变（Δ ≥ −2pp），仍 PASS；
变的是我们对「记忆带来多少提升」的表述：现在是「不伤害 + 1 对配对的方向性证据」。

## 再附：第四轮把 G6 做成了真实验（2026-10-27 凌晨）

第三轮的语料规格写在 docstring 里，测不出记忆价值。第四轮换成
`eval/fixtures/ledger-kata-blind`——**规格物理上不在仓库里**（任意校验算法、任意错误码前缀、
「四舍五入远离零」、降序稳定排序），只有种子记忆写着约定。

12 对（4 任务 × 3 种子，seatbelt 围栏）：**带记忆 12/12，不带 5/12，Δ = +58.3pp**。
在三条真正不可推导的约定上：控制臂 2/9，带记忆 9/9。耗时 131.8s vs 208.1s。

期间又抓到两个泄漏（`/tmp` 与 `/private/tmp` 的 deny 不等价；判完不删 oracle），
修完重跑受影响的 6 次控制，Δ 不变。详见 `docs/G6-quality-ab.zh.md` §11。
