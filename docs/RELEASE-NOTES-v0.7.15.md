# dsh-engram v0.7.15

**G1 换分母：只算「有节省机会的会话」。** 这是口径修订，不是调参。

## 1. 为什么

G1 原来的分母是「所有账本行」。问题在于：一个没有剪枝、没有压缩的会话，
**只有注入支出、没有节省入账，净值结构上必为负**——把它算进分母，测的是
「机制在这个会话里跑没跑」（那是 G2 的事），不是「跑起来后省没省到」。

本机 14 天实测：挂载会话 33 个，其中 **21 个（64%）确实发生过剪枝或压缩**。剩下 36%
无论产品多好都算负，永远拉低 G1。

## 2. 改成什么

- 分母 = 账本行里 `prunedChars + compactedChars > 0` 的会话（有节省机会）；
- 机会会话 < 5 时仍然只报数值、不给判定（一个会话不是分布）；
- 备注里同时给出「N/M 机会会话（共 K 行）」，全量数据不隐藏；
- G1b（长会话 ≥200 请求）同样换成机会会话。

已写进 [PROPOSAL §6](PROPOSAL-evolution.zh.md) 的指标表，`gate-audit` 的输出脚注同步。

## 3. 立刻的后果：G1 从 FAIL 变成「未测」

当前账本里 5 行，机会会话 **0** 个——因为：

- 压缩入账直到 v0.7.13 才真正能落地（事件形状 bug）；
- 会话级剪枝计数被重启清零过（v0.7.13 才修）。

也就是说，之前那个「G1 FAIL 20%」读的是**记账坏了**，不是产品差。「未测」比一个假
FAIL 更诚实。等 v0.7.13 的压缩入账真机落地、机会会话攒到 5 个，G1 才会给出第一个
有意义的判定。
