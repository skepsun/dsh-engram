# dsh-engram v0.7.10

**归因对称性**：宿主自己剪的枝，我们既不认领它的节省，也不替它付前缀失效的钱。

## 1. 15 小时后的账本（5 条会话行）

```
session-775f5173 (220 req)  avoid=0  inj=609,289  rw=1,224,725  engram=0  host=51,168  net=-1,711,542
session-746c0362 (383 req)  avoid=7,795,950 inj=749,802 rw=316,516  engram=7,841 host=13,032 net=+6,761,284
其余 3 行                    avoided=0（会话内从未剪枝/压缩）→ 结构性为负
```

两个信号：

1. **host 腿在真实使用中长到了 64,200 字符**（两个会话，我们全程没参与）；
2. **engram 腿停在 7,841**——15 小时内只剪到过那一次。

## 2. 这次修的是记账不对称

v0.7.9 的观察者对宿主剪枝做了两件事：计入 `hostPrunedChars`（对），**并且**按
`estimatePrefixChars + removed` 记 `rewriteCount/rewriteChars`（错）。后果：

- 宿主剪 51,168 字符 → 我们账上多出 1,224,725 字符的「前缀失效成本」（每次约 5 万 ×24 次）；
- 而宿主省下的东西我们不认领 → `avoidedChars` 仍是 0；
- 于是一个**我们全程没动过**的会话，净值 −1.71M。

这是双重记账的单边化：要么两侧都认，要么两侧都不认。选择后者——engram 的净收益只问
「engram 造成的成本与节省」，宿主的行为对我们既非收入也非支出。

- `notePrune(source: "host")` 只加 `hostPrunedChars`，不碰 `rewriteCount/rewriteChars/avoidedChars`。
- 测试：宿主剪枝不再产生 rewrite 计数（19/19 账本测试，441/441 全量）。

## 3. 对 L1 的判断（判据提前触发）

交接时定的判据是「host 腿长期远大于 engram 腿 → L1 该退场或只留阈值覆盖」。15 小时的数据已经
很难看：

- 一个 220 请求的真实会话，宿主自剪 4 次、共 51,168 字符；
- engram 的边界剪枝在那个会话里**一次都没触发**（只有 1 次 todo 写入，且没有完成项跨过水位线）；
- 而在有 todo 的会话里，我们剪到的那一次（7,841 字符）**确实抢在了宿主下一次装配之前**。

结论：L1 在「用 todo/goal 的长会话」里还有价值，在普通会话里完全空转。这不是 bug，是
边界源的覆盖率问题（L0 语料早就显示 ~62% 的会话没有任何 todo 进度）。默认开关要不要关，
取决于是否接受「只有规划型会话受益」。

## 已知边界

- 已经写进 `ledger.json` 的历史 rewrite 数字不会被追溯修改（那是一段有偏的记录，留着当证据）。
- host 腿仍用 `shadowedTokenCount × 4` 估算字符。
