# dsh-engram v0.7.14

**G7 从「未测」变成数字，G5 从「未测」变成 PASS，README 版本矩阵补齐到本期。**

## 1. G7：账本自身开销

新增 `npm run bench:ledger`（[eval/ledger-bench.mjs](eval/ledger-bench.mjs)）：在 200 个并发会话的账本上量每个热路径调用，分母用**本机真实 step 延迟**（最近 6 个会话 2,388 个 `step/start → step/end`，p50 5,080ms、p95 39,851ms），并额外给一个**严格下限**（300ms 请求，不含工具执行时间）：

| 操作 | 每次 | 占 p50 step |
|---|---|---|
| `tick()` | 0.22µs | 0.0000% |
| `noteInjection()` | 0.10µs | 0.0000% |
| `notePrune()`（含一次落盘） | 360µs | 0.0071% |
| `estimatePrefixChars()`（300 条消息 ≈120KB） | 391µs | 0.0077% |
| `summary()` | 224µs | 0.0044% |
| `tick + flush`（原子写） | 162µs | 0.0032% |

最坏一项（一次边界剪枝 = 剪枝 + 前缀遍历）**0.0126% of p50 step · 0.2137% of 300ms**，门是 0.5% → **PASS**。

用 p50 step 作分母会被长工具调用稀释，所以判据用严格下限：**即使按一次 300ms 的快速请求算，账本也只占 0.21%**。

`gate-audit` 新增 `--g7 <pct>`，把这个数字喂回门表（`--g7 0` 之外不传仍是「未测」——不猜）。
